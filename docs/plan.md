# 开发计划（plan）

> 本计划**不使用时间估计**（不写天/周/月/日期）。进度以阶段、依赖和可验证的退出标准表达；任务状态见 [tracking.md](tracking.md)。

## 1. 原则

1. 先规范、后代码：M0 未完成不进入 M1。
2. 纯逻辑先行：ini/设置/预设/校验/检测必须可无头测试；GUI 最后接。
3. 一次一个里程碑：未满足退出标准不得开工下一阶段。
4. 每个任务都可在 `tracking.md` 中追踪；提交信息说明“做了什么/为什么”。
5. 不引入第三方运行时依赖；确需引入时先新增决策记录。

## 3. 里程碑详情

### M0 脚手架与规范

**目标**：仓库可协作、可公开、可交接。

**任务**：`M0-T1` 目录与分级；`M0-T2` 双语 README；`M0-T3` AGENTS.md；`M0-T4` 文档体系；`M0-T5` git 跟踪与初始提交。

**产物**：`README.md`、`README.en.md`、`AGENTS.md`、`docs/` 全套、`private/` 占位（不入库）、`.gitignore`。

**退出标准**：
- `docs/` 与 `private/` 分级规则明确，`private/` 被忽略；
- 文档无时间估计、无本机路径、无游戏数据；
- 任务表存在且状态一致；
- 初始提交已推送到远端，`main` 跟踪 `origin/main`。

### M1 核心库

**目标**：不启动 GUI 也能安全读写 `totk.ini`。

**任务**：`M1-T1` 解析器；`M1-T2` 写入器（备份/原子写）；`M1-T3` 设置注册表；`M1-T4` 校验器；`M1-T5` 单元测试；`M1-T6` 独立审查修正（缺陷修复、回归测试与文档同步）。

**产物**：`src/totk_frontend/ini.py`、`settings.py`、`validate.py`；`tests/`。

**退出标准**：
- 真实/样例 `totk.ini` 的“读→改一个键→写”后，除目标行外逐字节一致；
- 未知键、注释、空行、节顺序全部保留；
- 大小写不敏感读取、同名键后者生效；
- CRLF/LF、中文路径、只读目录等边界有测试；
- 写失败可回滚；
- 覆盖率达到项目自定阈值：`src/totk_frontend` 语句覆盖率（AST 统计，多行语句按一条计）≥ 90%，用 `python tools/coverage_check.py` 测量（阈值在 M1 开始时确定，见 [design.md](design.md) 第 12 节 I8）。

### M2 预设与诊断

**目标**：一键把设置调到目标风格，并能解释为什么某些组合不安全。

**任务**：`M2-T1` 预设定义；`M2-T2` 应用与回滚；`M2-T3` `doctor`。

**产物**：`presets.py`、`doctor` 规则表、预设说明（并入 `settings.md`）。

**退出标准**：
- 预设只包含注册表中存在且已标注范围的键；
- 应用预设 = 差异集，未涉及的行不动；
- `doctor` 覆盖跨字段规则（见 `settings.md` 第 8 节），输出可操作建议；
- `--dry-run` 可预览全部改动。

### M3 CLI

**目标**：脚本化完成全部核心操作。

**任务**：`M3-T1` 命令框架与 `detect`；`M3-T2` `list/get/set/unset`；`M3-T3` `preset/apply/backup/restore`；`M3-T4` `launch/log/version`。

**产物**：`src/totk_frontend/cli.py`、`__main__.py`。

**退出标准**：每个命令有 `--help`、退出码约定、错误信息可读；无 GUI 依赖；在无游戏的机器上不崩溃。

### M4 GUI

**目标**：Savage Wind 风格的窗口，玩家不需要命令行。

**任务**：`M4-T1` 窗口骨架与状态栏；`M4-T2` 各设置页；`M4-T3` 预设/保存/恢复默认/备份/启动。

**产物**：`src/totk_frontend/gui.py`。

**退出标准**：
- 所有页面由注册表驱动，新增键无需改 UI 代码；
- 未保存修改有提示；保存后状态栏刷新；
- 设置项标注“立即生效/需重启”；
- 无 tkinter 环境给出明确提示并建议 CLI；
- 与 CLI 结果一致（同一核心库）。

### M5 安装检测与首次引导

**目标**：玩家第一次打开就知道要选哪个目录、缺什么。

**任务**：`M5-T1` 检测规则与结果模型；`M5-T2` 首次引导页；`M5-T3` 版本感知（1.1.0/1.2.1/1.4.3）。

**产物**：`install.py`、引导页。

**退出标准**：检测结果可解释（命中哪些标记、缺失哪些）；不同版本的键差异被标注；不自动执行安装器、不下载任何内容。

### M6 打包与发布准备

**目标**：可交付给玩家的构建与合规材料。

**任务**：`M6-T1` 打包（Windows 用 PyInstaller 生成免装 Python 的发布包）；`M6-T2` 发布检查单；`M6-T3` 许可证与第三方声明。

**产物**：构建脚本、`docs/release-checklist.md`、`LICENSE`、`THIRD_PARTY_NOTICES.md`。

**退出标准**：干净机器上按文档可运行；发布包不含游戏数据；检查单逐项通过；许可证已确定。

## 4. 决策记录

| ID | 决策 | 状态 | 说明 |
|---|---|---|---|
| D1 | 技术栈：Python 3.11+ / 仅标准库 / tkinter | 已定（可复议） | 与 TotK Recomp 安装器同栈；零第三方依赖；核心逻辑无头可测 |
| D2 | 显示名：TotK Frontend（仓库名同） | 已定 | 备选名 “Savage Sky” 记录在案，未采用 |
| D3 | 许可证 | **未定** | 需仓库所有者决定；参考项目均为 MIT；建议 MIT，但不得代定 |
| D4 | 是否代跑 TotK Recomp 安装器 | 已定：否 | 只检测与提示，避免打包/许可/安全边界扩大 |
| D5 | Linux 首发支持 | 未定（M6 评估） | Windows 为第一目标；Linux 代码路径保留 |
| D6 | GUI 与发布形态：`tkinter` 窗口 + PyInstaller 打包（玩家无需安装 Python） | 已定（用户选择方案 A） | 窗口沿用 D1 的标准库 `tkinter`；PyInstaller 仅在构建期使用（GPL 2.0 + 例外条款，允许打包分发），M6 需在 `THIRD_PARTY_NOTICES.md` 登记许可证并固定版本；Windows 包必须在 Windows 上构建，不做交叉编译；Rust 界面作为以后的可选替换方案记录在案，不进入当前里程碑 |

## 5. 非目标（重申）

- 不做重编译/运行时/渲染；不改游戏文件；不实现原生菜单集成；不提供游戏数据；不做下载器。

## 6. 变更控制

- 新增/调整里程碑：先改本文件，再改 `tracking.md`，同一提交内完成。
- 任何“时间估计”不得写入本文件或跟踪表。
- 计划变更需在提交信息中说明原因。
