# 文档分级与提交检查（DOC-POLICY）

本文件定义本项目文档的**唯一分级规则**。任何新增或修改文档都必须先通过本规则判定目录。

## 1. 两个目录，两个级别

| 目录 | 级别 | 是否提交 | 是否公开 | 用途 |
|---|---|---|---|---|
| `docs/` | 可提交、可公开 | 是 | 是 | 设计、计划、跟踪、设置参考、参考项目、合规、交接提示词 |
| `private/` | 仅本地 | **否** | 否 | 本机路径、测试记录、未验证推测、临时笔记、个人环境信息 |

`private/` 已被根目录 `.gitignore` 忽略。**不要**把需要公开的内容放进 `private/`，也不要把本机信息放进 `docs/`。

## 2. 判定表

| 内容 | 目录 | 原因 |
|---|---|---|
| 产品设计、里程碑、任务跟踪 | `docs/` | 协作必需、无敏感信息 |
| `totk.ini` 键名、默认值、范围、生效时机 | `docs/` | 来自公开文档，玩家需要 |
| 参考项目清单、许可证、参考范围 | `docs/` | 合规必需 |
| 合规声明、免责声明 | `docs/` | 公开 |
| 交接提示词（对下一个代理） | `docs/` | 需随仓库传递 |
| 本机绝对路径（如 `D:\Games\...`） | `private/` | 设备相关、无公开价值 |
| 未验证的猜测、逆向记录草稿 | `private/` | 可能错误、可能含敏感细节 |
| 本地测试日志、截图、录屏 | `private/` | 可能含游戏画面/路径/账号信息 |
| 密钥文件、`prod.keys` 内容、固件路径 | **禁止出现** | 合规红线（见 [compliance.md](compliance.md)） |
| 游戏文件、`exefs/`、`romfs/`、生成的 C、`totk.exe` | **禁止出现** | 合规红线 |

## 3. 命名与格式

- 文件名用英文小写 kebab-case（如 `doc-policy.md`），内容以简体中文为主。
- 根目录 README 必须双语：`README.md`（中文）+ `README.en.md`（英文），顶部互链、结构一致。
- 文档内引用其他文档使用相对路径链接；引用外部项目必须给链接与许可证。

## 4. 提交前检查清单

提交前逐项确认：

```bash
# 1) private/ 没有被暂存
git status --porcelain | grep -E '^\?\? private/|^A  private/' && echo 'ERROR: private/ 被暂存' || echo OK

# 2) private/ 确实被忽略
git check-ignore -v private/ 2>/dev/null || echo 'ERROR: private/ 未被忽略'

# 3) 没有游戏数据/密钥类文件进入索引
git diff --cached --name-only | grep -Ei '(\.nsp|\.xci|\.nsz|\.xcz|prod\.keys|\.tik|\.cert|\.nca|\.romfs|exefs/|romfs/|totk\.exe)' && echo 'ERROR: 疑似游戏数据' || echo OK
```

且人工确认：文档中无本机绝对路径、无密钥、无游戏画面、无未公开的个人信息；文档中无具体时间/工期估计。

## 5. 变更流程

1. 新增文档前先按第 2 节判定目录。
2. 若内容介于两者之间：**先放 `private/`**，确认可公开后再移入 `docs/`。
3. 修改分级规则本身，必须在提交信息中说明动机。
